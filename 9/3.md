### 🌀 Switching Branches and Folders
- When you **switch from branch B to branch A**, Git updates your working directory to match the snapshot of branch A.
- If branch A doesn’t have the `XYZ` folder (because it never had `.gitkeep` or any files inside it), Git will remove that folder from your working directory **as long as it’s clean**.
- But if you created files in `XYZ` that are **untracked** (not added to Git), Git won’t delete them when you checkout branch A. They’ll remain in your working directory as “extra” files.

### 🔎 Key Scenarios
| Situation | What happens when switching to branch A |
|-----------|------------------------------------------|
| `XYZ` exists in branch B with tracked files | Folder disappears in branch A if it’s not part of that branch. |
| `XYZ` exists in branch B with only `.gitkeep` tracked | Folder disappears in branch A if `.gitkeep` isn’t present there. |
| `XYZ` has untracked files (never committed) | Folder and files remain, because Git doesn’t touch untracked files. |
| `XYZ` has ignored files (via `.gitignore`) | They remain, since Git ignores them but doesn’t delete them. |

### ✅ In short
- Git only guarantees your working directory matches the branch snapshot.  
- If files/folders are tracked in one branch but not in another, they’ll vanish when you switch.  
- If files are untracked, they’ll hang around until you manually delete them.

---

A useful command here is:

```bash
git status
```

It will show you if those leftover files are untracked after switching. If you want to clean them up, you can run:

```bash
git clean -fd
```

That removes untracked files and directories, giving you a clean slate.
