## 📝 Key Takeaways
- **Git hooks**: Scripts that run automatically at certain points in Git’s workflow (e.g., `pre-commit`, `pre-push`). They enforce rules or automate tasks.
- **Custom hook path**:  
  ```powershell
  git config core.hooksPath scripts/hooks
  ```  
  → Redirects Git to look for hooks in `scripts/hooks` instead of `.git/hooks`.
- **Hook test meaning**: Running a push after configuring hooks is a way to confirm that your hook scripts (like `pre-push`) are firing correctly.
- **HEAD vs main**:
  - `git push origin main` → Pushes your local `main` branch to remote `main`.
  - `git push origin HEAD:main` → Pushes *whatever branch you’re currently on* (e.g., `feature/login`) into remote `main`.  
    This is why it’s used when you’re on a feature branch but want to update `main` directly.
- **Risk factor**: Directly pushing feature branch commits into `main` bypasses Pull Requests and review processes. Many teams restrict this to avoid conflicts.

---

## ✅ Best Practice
- Use **Pull Requests** for merging feature branches into `main` — safer, with review and CI checks.  
- Reserve `HEAD:main` for special cases (like automation or solo projects) where you intentionally want to push your current branch directly into `main`.

---

Think of it like this:  
- `main` → “Push my local `main` branch.”  
- `HEAD:main` → “Push whatever I’m on right now into remote `main`.”  

That’s the essence of your “hook test” push.
